# Git, терминал и VS Code — шпаргалка для unik

Репозиторий: [jstnYBN/unik](https://github.com/jstnYBN/unik).

Все команды из последних ответов собраны здесь с уточнениями и примерами. Это практическая шпаргалка для лабораторных, а не полный справочник всех возможностей Git.

**Запомни цепочку:** `status → pull → работа → add → commit → push`.

## 1. Как пользоваться примерами

- Команды вводи по одной в терминале. Примеры рассчитаны на **PowerShell в Windows**, в том числе терминал VS Code.
- Команды Git обычно выполняются внутри папки `unik`, а не внутри служебной папки `.git`.
- `main` — основная ветка; `para` — ветка для работы на парах в примерах этой шпаргалки. Их наличие и правила использования проверяй в своём репозитории.
- `origin` — короткое имя удалённого репозитория; `origin/para` — локальное представление его ветки после `fetch`.
- `HEAD` — текущий коммит; индекс (staging area) — изменения, подготовленные к коммиту.
- `ТВОЯ_ПОЧТА`, `folder-name` и пути к лабораторным замени своими значениями. `web-programming/lab15` ниже — пример пути.
- Не запускай все блоки подряд: некоторые показывают альтернативы или отмену действий.

## 2. Терминал и VS Code

| Команда | Что делает |
|---|---|
| `pwd` | Показывает текущую папку |
| `ls` | Показывает файлы и папки |
| `ls -Force` | Показывает также скрытые элементы в PowerShell |
| `cd unik` | Переходит в папку `unik` |
| `cd ..` | Переходит на уровень выше |
| `cd "C:\Projects\unik"` | Переходит по полному пути; кавычки нужны для пробелов |
| `mkdir lab15` | Создаёт папку `lab15` |
| `cls` | Очищает экран терминала; файлы не удаляет |
| `code .` | Открывает текущую папку в VS Code |
| `code README.md` | Открывает файл в VS Code |
| `code -n .` | Открывает текущую папку в новом окне VS Code |
| `git --version` | Проверяет доступность и версию Git |
| `code --version` | Проверяет доступность и версию VS Code через терминал |

**Правильно: `code .`, а не `. code`.** Точка означает текущую папку. Это команда VS Code, не Git. См. [официальную справку VS Code](https://code.visualstudio.com/docs/configure/command-line).

В VS Code: **Terminal → New Terminal** — открыть терминал, **Ctrl+S** — сохранить файл, **Ctrl+Shift+V** — открыть предпросмотр Markdown. В просмотре истории Git клавиша `q` закрывает постраничный просмотр.

Если `git` или `code` не распознаётся, установи соответствующую программу с официального сайта и проверь добавление в `PATH`. После установки открой терминал заново. На чужом ПК установку согласуй с владельцем.

В обычном `cmd.exe` вместо `ls` используй `dir`, а вместо `pwd` — `cd` без аргументов. В Git Bash экран очищается командой `clear`.

## 3. Настройка Git на новом ПК

### Личный компьютер

Установи [Git](https://git-scm.com/downloads) и [VS Code](https://code.visualstudio.com/). Один раз задай автора будущих коммитов:

```powershell
git config --global user.name "jstnYBN"
git config --global user.email "ТВОЯ_ПОЧТА"
git config --global init.defaultBranch main
git config --global core.editor "code --wait"
```

Укажи свою подтверждённую почту GitHub либо свой адрес `noreply` из настроек GitHub. Не копируй чужой адрес. `init.defaultBranch` задаёт имя ветки для новых репозиториев, существующие ветки не переименовывает.

Проверка:

```powershell
git config --list
git config --show-origin --get user.name
git config --show-origin --get user.email
```

Не публикуй полный вывод настроек без проверки: там могут быть личные данные или чувствительные адреса.

### Чужой компьютер / университет

После клонирования настрой автора **только для своей копии репозитория**:

```powershell
cd unik
git config --local user.name "jstnYBN"
git config --local user.email "ТВОЯ_ПОЧТА"
```

`--global` действует на все репозитории текущего пользователя Windows; `--local` — на текущий репозиторий. Имя и почта автора **не выполняют вход в GitHub**.

Для отправки через HTTPS потребуется авторизация, например через менеджер учётных данных и браузер, либо токен. Обычный пароль аккаунта GitHub для Git по HTTPS не используется. Подробнее: [аутентификация GitHub](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/about-authentication-to-github).

> **Безопасность на чужом ПК.** По возможности отправляй работу со своего устройства. Не сохраняй пароль, токен или личный SSH-ключ; не вставляй токен в URL, команды, README и исходники. Приватный режим браузера не защищает от вредоносных программ и сохранения данных другими приложениями. После работы выйди из GitHub в браузере и из своего аккаунта в VS Code; проверь, не остались ли твои данные GitHub в Диспетчере учётных данных Windows. Удаляй только собственные записи. При утечке отзови токен или ключ с доверенного устройства. Удаление папки проекта само по себе не удаляет сохранённый вход.

## 4. Клонирование unik и выбор ветки

Если копии ещё нет, открой терминал в папке, где хочешь хранить проект:

```powershell
git clone https://github.com/jstnYBN/unik.git
cd unik
git remote -v
git fetch origin
git branch -a
```

Если локальная `para` уже есть:

```powershell
git switch para
```

Если есть только `origin/para`, создай локальную ветку с отслеживанием:

```powershell
git switch --track origin/para
```

Если `para` нет ни локально, ни на GitHub, создай её от актуальной `main`:

```powershell
git switch main
git pull --ff-only origin main
git switch -c para
git push -u origin para
```

После выбора существующей `para` обнови её и открой редактор:

```powershell
git pull --ff-only origin para
code .
```

Если `main` видна только как `origin/main`, используй `git switch --track origin/main`. Если веток нет, сначала нужен первый коммит в пустом репозитории.

**Если проект уже скачан, повторный `clone` не нужен:** перейди в существующую папку и начни с `git status`.

## 5. Каждый день: университет → дом

### Перед началом работы — и дома, и на паре

```powershell
cd "C:\Projects\unik"
git status
git switch para
git pull --ff-only origin para
code .
```

Замени путь своим. Если `status` показывает незавершённые изменения, сначала сохрани их коммитом или через `stash` (раздел 10). Если `pull --ff-only` отказал из-за расхождения истории, перейди к разделу 11.

### После выполнения лабораторной

Сохрани файлы в VS Code, затем:

```powershell
git status
git diff
git add -- web-programming/lab15
git diff --staged
git commit -m "Добавить лабораторную 15"
git push origin para
git status
```

Путь в `git add` должен существовать. Для нового README в корне используй `git add -- README.md`. Чтобы подготовить все изменения внутри текущей папки и её подпапок, можно использовать `git add .`, но сначала проверь список файлов: не добавляй пароли, токены, `.env` и лишние архивы.

`commit` сохраняет снимок локально; только успешный `push` отправляет его на GitHub. Проверь ветку `para` на сайте перед уходом. Дома выполни тот же блок «Перед началом работы», чтобы получить отправленную работу.

## 6. Основные команды Git

| Команда | Назначение |
|---|---|
| `git init` | Создать репозиторий в текущей папке; для существующего `unik` не нужен |
| `git clone https://github.com/jstnYBN/unik.git` | Создать локальную копию репозитория |
| `git status` | Показать ветку, изменения и подготовленные файлы |
| `git status -sb` | Краткий статус и сведения об отслеживаемой ветке |
| `git add .` | Подготовить добавления, изменения и удаления внутри текущей папки |
| `git add -- README.md` | Подготовить конкретный файл |
| `git commit -m "Описание"` | Создать коммит из подготовленных изменений |
| `git diff` | Показать неподготовленные изменения отслеживаемых файлов |
| `git diff --staged` | Показать изменения, которые войдут в коммит |
| `git log --oneline` | Краткая история коммитов |
| `git log --oneline --graph --all --decorate` | История с ветками |
| `git show HEAD` | Показать последний коммит текущей ветки |
| `git fetch origin` | Обновить сведения об удалённых ветках, не объединяя их с текущей |
| `git pull` | Получить и интегрировать изменения отслеживаемой ветки; поведение зависит от настроек |
| `git pull --ff-only origin para` | Обновить текущую ветку из `para` только без расхождения истории |
| `git push` | Отправить ветку согласно настроенной привязке и настройкам push |
| `git push origin para` | Отправить локальную `para` в `para` на `origin` |
| `git help status` | Открыть справку по команде |

Новый неотслеживаемый файл обычно не показывается в `git diff`: смотри `git status`, а после `add` — `git diff --staged`.

**Не выполняй `git init` внутри каждой лабораторной:** если папка уже входит в `unik`, достаточно общего репозитория. Вложенный `.git` может создать отдельный репозиторий и осложнить сохранение файлов.

## 7. Ветки main и para

| Команда | Назначение |
|---|---|
| `git branch` | Локальные ветки; текущая отмечена `*` |
| `git branch -a` | Локальные и известные удалённые ветки |
| `git branch -vv` | Привязки локальных веток |
| `git branch lab15` | Создать ветку без переключения |
| `git switch -c lab15` | Создать ветку от текущего коммита и переключиться |
| `git switch main` | Переключиться на существующую локальную `main` |
| `git switch para` | Переключиться на `para`; при однозначной удалённой ветке Git может создать привязку автоматически |
| `git switch --track origin/para` | Явно создать локальную `para`, отслеживающую `origin/para` |
| `git merge para` | Влить `para` **в текущую ветку** |
| `git branch -d lab15` | Удалить локальную ветку с проверкой её слитости |
| `git push origin --delete lab15` | Удалить ветку на GitHub; затрагивает других участников |

Перед удалением ветки переключись на другую и убедись, что нужные коммиты сохранены.

### Перенести завершённую работу из para в main

Только когда работа готова и рабочая папка чистая:

```powershell
git switch para
git pull --ff-only origin para
git switch main
git pull --ff-only origin main
git merge para
git push origin main
git switch para
```

При конфликте остановись и выполни раздел 11. Если `main` защищена, отправь `para` и создай Pull Request `para → main` на GitHub вместо прямого push в `main`.

## 8. Подключение удалённого репозитория

| Команда | Назначение |
|---|---|
| `git remote -v` | Посмотреть адреса удалённых репозиториев |
| `git remote add origin https://github.com/jstnYBN/unik.git` | Добавить `origin`, если его ещё нет |
| `git remote set-url origin https://github.com/jstnYBN/unik.git` | Изменить адрес существующего `origin` |
| `git remote remove origin` | Убрать локальное подключение и его настройки; репозиторий на GitHub остаётся |
| `git push -u origin main` | Отправить `main` и настроить её отслеживание |
| `git push -u origin para` | Отправить `para` и настроить её отслеживание |
| `git pull origin main` | Получить и интегрировать `main` **в текущую ветку** |

После `clone` подключение `origin` уже создано. Не выполняй `remote add origin` повторно. Команда `pull origin main` не переключает ветку: для обновления самой `main` сначала выполни `git switch main`. Для предсказуемого ежедневного обновления используй `pull --ff-only`. См. [справку git pull](https://git-scm.com/docs/git-pull).

## 9. Sparse checkout — работать только с нужной папкой

Sparse checkout ограничивает файлы в рабочей папке. Сам по себе он не сокращает историю. `--filter=blob:none` откладывает загрузку содержимого файлов до необходимости; сервер должен поддерживать фильтр. `--depth 1` отдельно ограничивает историю. Подробнее: [sparse checkout](https://git-scm.com/docs/git-sparse-checkout) и [git clone](https://git-scm.com/docs/git-clone).

### Новая копия: папка web-programming из ветки para

Выполняй, если `para` уже существует на GitHub. Папка назначения `unik-para` должна быть новой:

```powershell
git clone --filter=blob:none --sparse --branch para https://github.com/jstnYBN/unik.git unik-para
cd unik-para
git sparse-checkout set --cone web-programming
code .
```

В cone-режиме сохраняются также файлы корня, например README. Не показанные папки не удаляются из репозитория.

### Добавить ещё одну папку или вернуть все

```powershell
git sparse-checkout add folder-name
git sparse-checkout list
```

`add` дополняет выбор; `set` заменяет весь список выбранных папок.

После сохранения текущих изменений вернуть полный рабочий каталог можно так:

```powershell
git sparse-checkout disable
```

Для уже скачанного репозитория перейди в его корень и выполни `git sparse-checkout set --cone web-programming` — повторное клонирование не нужно.

### Вариант с короткой историей

Если нужна только недавняя версия `para`, вместо предыдущего клонирования:

```powershell
git clone --depth 1 --filter=blob:none --sparse --branch para https://github.com/jstnYBN/unik.git unik-short
cd unik-short
git sparse-checkout set --cone web-programming
```

`--depth 1` по умолчанию также ограничивает клонирование одной веткой. Для регулярной работы с `main` и `para` удобнее вариант без `--depth`.

В короткой копии полную историю доступной ветки можно получить командой `git fetch --unshallow origin`. Другие ветки автоматически от этого не появятся. Если нужна `main`, добавь её в отслеживаемые ветки:

```powershell
git remote set-branches --add origin main
git fetch origin
git switch --track origin/main
```

`switch --track` используй только если локальной `main` ещё нет. Если осталась граница короткой истории и нужна полная история, выполни `git fetch --unshallow origin`; для уже полной копии этот флаг не нужен.

## 10. Отмена изменений и временное сохранение

Перед отменой посмотри `git status`, `git diff` и `git diff --staged`. Несохранённую работу сначала скопируй в безопасное место или отложи через `stash`.

| Ситуация | Команда | Результат и риск |
|---|---|---|
| Добавил файл в индекс по ошибке | `git restore --staged -- README.md` | Убирает из индекса, оставляя содержимое файла |
| Нужно отменить неподготовленные правки файла | `git restore -- README.md` | **Теряет эти правки**: берёт содержимое из индекса |
| Отменить последний локальный коммит | `git reset --soft HEAD~1` | Сдвигает ветку назад; изменения остаются в индексе |
| Отменить опубликованный обычный коммит | `git revert HEAD` | Создаёт новый отменяющий коммит; история сохраняется |
| Отложить изменения отслеживаемых файлов | `git stash` | Сохраняет их во временное хранилище |
| Отложить также новые неотслеживаемые файлы | `git stash push -u -m "Работа перед обновлением"` | Игнорируемые файлы не включает |
| Посмотреть отложенные изменения | `git stash list` | Показывает список |
| Вернуть последние изменения и оставить запасную запись | `git stash apply` | Запись остаётся в stash |
| Вернуть последние изменения и убрать запись при успехе | `git stash pop` | При конфликте запись сохраняется |
| Посмотреть прежние положения HEAD | `git reflog` | Может помочь найти потерянный коммит |

`HEAD~1` требует существования родительского коммита. `reset --soft` применяй для ещё не отправленных коммитов; для опубликованных обычно выбирай `revert`. Отмена merge-коммита требует отдельного выбора родителя — не применяй к нему пример `revert HEAD` вслепую. См. [справку git reset](https://git-scm.com/docs/git-reset).

Пример временного сохранения перед обновлением:

```powershell
git stash push -u -m "Незаконченная лабораторная"
git pull --ff-only origin para
git stash pop
git status
```

Stash хранится только в этой локальной копии и не отправляется обычным `push`. Для переноса работы между компьютерами нужен коммит и push.

## 11. Частые ошибки и конфликты

| Сообщение / ситуация | Что сделать |
|---|---|
| `not a git repository` | Проверить `pwd`, перейти в `unik`; не создавать новый репозиторий наугад |
| `remote origin already exists` | Проверить `git remote -v`; при необходимости использовать `remote set-url` |
| `pathspec ... did not match` при выборе ветки | Выполнить `git fetch origin`, посмотреть `git branch -a` |
| У `para` нет upstream | Выполнить `git push -u origin para` для первой отправки |
| `nothing to commit` | Сохранить файл в редакторе, проверить папку, ветку и `git status` |
| Push отклонён: `non-fast-forward` | Получить изменения и разобраться с историей; не использовать force как обычное решение |
| `Permission denied` / `Authentication failed` | Проверить аккаунт, адрес `origin`, права и способ входа |
| `dubious ownership` на общем ПК | Проверить владельца и путь; лучше создать свою копию. Не отключать проверку для всех папок через `safe.directory '*'` |

Если `pull --ff-only` отказал из-за расхождения локальных и удалённых коммитов, сначала сохрани свои изменения, затем посмотри историю:

```powershell
git fetch origin
git log --oneline --graph --all --decorate
```

Если ты находишься в `para` и хочешь объединить обе истории, при чистой рабочей папке:

```powershell
git merge origin/para
```

При конфликте:

1. Выполни `git status`, открой конфликтующие файлы.
2. Выбери нужное содержимое, убери маркеры `<<<<<<<`, `=======`, `>>>>>>>`, сохрани файлы.
3. Добавь исправленные файлы через `git add -- путь_к_файлу`.
4. Заверши слияние командой `git commit`, затем выполни `git push origin para`.

Если хочешь отказаться от незавершённого слияния, используй `git merge --abort`. Лучше начинать слияние с чистой рабочей папкой: восстановление прежних незакоммиченных изменений не всегда возможно.

Конфликт после `stash pop` разрешай в файлах и через `git add`; `git merge --abort` для него не подходит. Запись stash при таком конфликте остаётся — не удаляй её, пока не проверишь восстановленную работу.

## 12. Опасные команды — не запускать без понимания

Это справочная таблица, **не последовательность для выполнения**.

| Команда | Чем опасна | Что проверить заранее |
|---|---|---|
| `git restore .` | Теряет неподготовленные правки отслеживаемых файлов в текущей папке и ниже | `git diff`, копия нужных файлов |
| `git reset --hard HEAD` | Сбрасывает индекс и отслеживаемые файлы; мешающие восстановлению неотслеживаемые пути тоже могут быть удалены | Резервная копия, `status`, оба вида `diff` |
| `git reset --hard origin/main` | Кроме сброса файлов перемещает **текущую ветку** на `origin/main` | Правильная ли ветка; сохранены ли локальные коммиты |
| `git clean -fd` | Удаляет неотслеживаемые файлы и папки, кроме игнорируемых по умолчанию | Сначала `git clean -nd` — только просмотр |
| `git clean -fdx` | Удаляет также игнорируемые файлы: например `.env` и локальные настройки | Сначала `git clean -ndx`; резервная копия |
| `git push --force` | Может перезаписать удалённую историю и убрать чужие коммиты из ветки | Для обычной работы не нужен |
| `git push --force-with-lease` | Тоже переписывает историю, но проверяет ожидаемое состояние удалённой ветки | Это дополнительная проверка, а не гарантия безопасности |
| `git branch -D lab15` | Принудительно удаляет локальную ветку, даже если её работа не слита | Сохранены ли её коммиты |
| `git push origin --delete para` | Удаляет ветку на GitHub | Нужна ли ветка другим и есть ли копия |
| `git stash drop` / `git stash clear` | Удаляет одну / все записи временного хранилища | Восстановлены ли нужные файлы |
| Удаление папки `.git` | Лишает эту копию локальной истории, веток и настроек Git | Не использовать как способ исправления ошибок |

Git обычно не может вернуть содержимое файлов, которые никогда не были сохранены в коммите или stash. `reflog` помогает искать коммиты, но не служит резервной копией всех файлов.

## 13. Что не отправлять в репозиторий

Пример содержимого `.gitignore` — добавляй только подходящие проекту правила:

```gitignore
.env
.env.*
!.env.example
node_modules/
*.log
```

`.gitignore` не прекращает отслеживание уже добавленных файлов и не удаляет секреты из прошлой истории. Если секрет попал на GitHub, сначала отзови или замени его. Не добавляй `.git` вручную и не храни токены в README.

## 14. Самый короткий вариант для запоминания

Начало работы (при чистом статусе):

```powershell
git status
git switch para
git pull --ff-only origin para
code .
```

Завершение работы (после сохранения файлов):

```powershell
git status
git diff
git add .
git diff --staged
git commit -m "Описание выполненной работы"
git push origin para
```

**Сначала проверяй папку и ветку. Перед коммитом — содержимое изменений. Перед уходом — успешный push.**
